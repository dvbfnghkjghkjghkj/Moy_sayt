# Портфолио работ

Сайт-портфолио для IT-проектов: главная с указателем работ, страницы проектов,
страница «О себе» и отдельная админка для добавления работ без кода.

Работает на Node.js 18+ и **не имеет внешних зависимостей** — `npm install` не нужен.

## Запуск

Двойной клик по `start-server.cmd` — запустит сервер и через пару секунд
откроет сайт в браузере. Окно закрывать не нужно: это и есть работающий сервер,
Ctrl+C или закрытие окна его останавливает.

Или вручную:

```powershell
node server.js
```

Откройте http://127.0.0.1:5173 — сайт, http://127.0.0.1:5173/admin — управление.

Другой порт:

```powershell
$env:PORT=5174; node server.js
```

## Вход в админку

При первом запуске пароль создаётся автоматически и печатается в консоль
(он же хранится в виде хэша в `data/auth.json`).

Сменить пароль:

```powershell
node scripts/set-password.js "новый пароль"
```

Пароль забыт — удалите `data/auth.json` и перезапустите сервер: появится новый,
работы при этом не пострадают.

## Как добавить работу

1. `/admin` → **Новая работа**.
2. Название, год, категория, стек. Категория подставляется из списка, но можно вписать свою.
3. Краткое описание попадает в список работ, полное — на страницу проекта.
   Пустая строка — новый абзац, `- ` в начале строки — пункт списка.
4. Обложка: PNG, JPEG, WebP, GIF или AVIF до 8 МБ, лучше 4:3. Дополнительные
   изображения — там же, любое количество. Они же листаются во всплывающей
   карточке указателя работ.
5. Ссылки: подпись + адрес (https://…).
6. **Сохранить**. Галочка «Опубликовано» управляет видимостью — скрытая работа
   отвечает 404 и не показывается в списке.

Переключатель «видно» в списке публикует и снимает с публикации одним кликом.

## Настройки сайта

`/admin` → **Настройки**: имя, кто вы, вступление на главной, статус, город,
стек, почта, Telegram, WhatsApp, MAX, тема письма, первая фраза в WhatsApp,
текст «О себе», смена пароля.

## Что где лежит

```
server.js            сервер: страницы, API, загрузка файлов
start-server.cmd     запуск двойным кликом (Windows)
app.js               точка входа для Passenger (uCoz)
lib/store.js         хранилище data/db.json (атомарная запись)
lib/contacts.js      ссылки на почту, WhatsApp и MAX, метка в сообщении
lib/auth.js          пароль (scrypt), сессии, лимит попыток входа
lib/views.js         HTML-шаблоны страниц
lib/plural.js        «1 работа / 2 работы / 5 работ»
scripts/build-static.js  сборка статики для GitHub Pages
static.config.json   настройки этой сборки
docs/                результат сборки — его и публикуют
public/css           стили сайта и админки
public/js            превью работ, логика админки
public/uploads       загруженные изображения
public/admin.html    каркас админки
data/db.json         работы и настройки
data/auth.json       хэш пароля
```

## Резервная копия

Скопируйте две папки: `data/` и `public/uploads/`. Этого достаточно, чтобы
восстановить сайт целиком. Восстановление — вернуть папки на место и
перезапустить сервер.

## Как это устроено

- Страницы собираются на сервере, а не в браузере: ссылки на работы открываются
  и без JavaScript, поисковики видят полный текст.
- Данные — JSON-файл; запись атомарная (временный файл + переименование),
  повреждённый файл при старте откладывается в сторону как `db.json.broken-…`.
- Пароль хранится только как scrypt-хэш; вход выдаёт подписанную HttpOnly-cookie
  на 7 дней — она переживает перезапуск сервера. На изменяющие запросы требуется
  служебный заголовок (защита от CSRF), не более 8 неудачных попыток входа за 10 минут.
- Загрузка проверяет настоящий тип файла по сигнатуре, а не по расширению.
  SVG не принимается: в нём можно спрятать скрипт.
- Контакты — пиктограммы в подвале, на странице работы и в «О себе». Кнопка
  «Написать письмо» открывает почту с готовой темой, WhatsApp — с первой фразой,
  чтобы сообщение не терялось в общем списке. Telegram и MAX в личный чат текст
  подставлять не умеют — там ссылка ведёт прямо в профиль.
- В «Указателе работ» при наведении на строку всплывает карточка с изображениями
  работы. Ведёте курсор вдоль строки — кадры сменяют друг друга: положение
  курсора по горизонтали задаёт кадр, точки внизу показывают, сколько их всего.
  С клавиатуры (Tab) показывается первый кадр.
- Шрифты — Golos Text и JetBrains Mono с Google Fonts. Для полностью офлайн-версии
  скачайте `.woff2` в `public/fonts` и замените ссылки в `lib/views.js` и
  `public/admin.html`.

## Публикация на GitHub Pages

Сайт можно выложить статикой — без сервера и хостинга:

```powershell
npm run build
```

Готовые файлы появятся в `docs/`: страницы, стили, скрипт превью, `robots.txt`,
`sitemap.xml`, `.nojekyll` и все изображения из `public/uploads`.

Путь и адрес сборка определяет по `.git/config`, если репозиторий уже привязан
к GitHub (`origin` → `github.com/логин/репозиторий`). Иначе задайте их явно:

```powershell
node scripts/build-static.js --base=/Moy_sayt/ --url=https://nick.github.io/Moy_sayt/
```

- `--base` — путь, по которому лежит сайт: для репозитория `nick/Moy_sayt` это
  `/Moy_sayt`, для репозитория `nick.github.io` — пусто.
- `--url` — адрес сайта для `sitemap.xml` и `robots.txt`.
- `--out`, `--cname` — каталог сборки и свой домен.

Постоянные значения можно записать в `static.config.json`; ключи командной
строки его перекрывают.

Дальше:

1. Закоммитьте каталог `docs/`.
2. В репозитории: **Settings → Pages → Source: Deploy from a branch**, ветка
   `main`, папка `/docs`.
3. Через минуту сайт откроется по адресу из `--url`.

Свой домен: впишите его в `cname` (появится файл `CNAME`) и оставьте `base`
пустым.

Чего в статике нет: админки и серверных API. Работы добавляются локально в
`/admin`, затем `npm run build` и коммит `docs/`. Ссылка «Управление» в подвале
на опубликованном сайте скрывается автоматически.

Обновление одной командой:

```powershell
npm run publish
```

Она пересобирает `docs/`, делает коммит и отправляет на GitHub — Pages
пересоберёт сайт сам.

То же самое есть в админке: кнопка **«Опубликовать»** в шапке. Она запускает
сборку, коммит и push, а в окне показывает журнал шагов. Кнопке нужен доступ
к `git` и настроенный вход на GitHub в системе; если сервер запущен в песочнице
без права запускать процессы, кнопка вернёт ошибку — тогда используйте
`npm run publish` в терминале.

## Границы применимости

Один пароль, один человек, JSON-хранилище. До нескольких сотен работ это
быстро и надёжно; для нескольких редакторов и тысяч записей понадобилась бы
база данных.
