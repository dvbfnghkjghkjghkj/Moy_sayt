# Публикация на uCoz

uCoz умеет запускать собственные Node.js-приложения
([инструкция](https://www.ucoz.ru/help/tools/servernye-skripty-na-ucoz)):
код кладётся в каталог `app_node`, приложение открывается по адресу
`https://<аккаунт>.usites.app`, данные можно хранить в файлах или в MySQL.

Нашему сайту MySQL не нужна: работы и настройки лежат в `data/db.json`,
картинки — в `public/uploads`.

## Перед загрузкой

1. Задайте постоянный пароль (это же создаст `data/auth.json`):

   ```powershell
   node scripts/set-password.js "длинный пароль"
   ```

   Загрузите `data/auth.json` вместе с проектом — тогда вход в `/admin`
   будет с этим паролем. Если файл не загружать, uCoz создаст случайный пароль
   и напишет его в лог приложения (Passenger Log), но так пароль увидеть сложнее.

2. Убедитесь, что в `data/db.json` то, что нужно опубликовать. Примеры работ
   можно удалить заранее в админке кнопкой «удалите одним нажатием».

## Шаг 1. Создать приложение

Панель управления сайтом → **Серверные скрипты** → вкладка **Node.js** →
**Создать приложение**.

## Шаг 2. Загрузить файлы

Через панель («Загрузить файлы») или по FTP (вкладка «FTP для серверных скриптов»)
загрузите в `app_node`:

```
app.js
server.js
package.json
lib/
public/
data/
```

`node_modules` не нужны — внешних зависимостей у проекта нет.
Служебные папки `scripts/`, `README.md`, `DEPLOY-UCOZ.md` можно не загружать.

## Шаг 3. Запустить

- Если в панели есть кнопка **«Использовать package.json»** — нажмите её;
  `Run NPM Install` ничего не установит (зависимостей нет), это нормально.
- Нажмите **Restart**.
- Откройте `https://<аккаунт>.usites.app` — должна открыться главная.
- Откройте `https://<аккаунт>.usites.app/admin` и войдите.

Сервер слушает порт из переменной `PORT`, которую передаёт Passenger, поэтому
ничего настраивать не нужно.

## Шаг 4. Проверить после публикации

- Главная, страница работы, «О себе» открываются.
- `https://<аккаунт>.usites.app/robots.txt` отвечает.
- Вход в `/admin` работает, новая работа сохраняется и видна на сайте.
- Загрузка обложки проходит (проверьте, что в `public/uploads` появился файл).

## Обновление сайта

1. Через FTP замените изменённые файлы в `app_node`.
2. Нажмите **Restart** (для Node.js изменения подхватываются только после перезапуска).
3. Проверьте главную и `/admin`.

Данные (`data/db.json`, `public/uploads`) при обновлении не трогайте — иначе
потеряете работы. Перед обновлением скачайте их копию.

## Если что-то не работает

| Симптом | Что проверить |
| --- | --- |
| Белый экран, 502 | Passenger Log в каталоге `logs` — чаще всего неверный файл запуска (`app.js`) или ошибка в коде |
| После правки файлов ничего не изменилось | Нажать Restart |
| Не сохраняются работы | Права на запись в `app_node/data` (и `app_node/public/uploads`) |
| «Неверный пароль», хотя пароль верный | Загружен ли `data/auth.json`; при необходимости пересоздайте пароль и загрузите файл заново |
| Картинка не загружается | Файл больше 8 МБ или формат не PNG/JPEG/WebP/GIF/AVIF |

## Ограничения тарифа серверных скриптов

500 МБ диска, 50 ГБ трафика в месяц, 1 ГБ памяти, 3 базы MySQL.
Для портфолио с изображениями это запас на сотни работ, но за размером
`public/uploads` стоит следить: 500 МБ — общий лимит.

## Домен

Приложение живёт на `usites.app`. Основной сайт uCoz и приложение — разные
системы; связать их можно ссылкой с сайта на приложение (и наоборот) или
через адрес вида `https://<ваш-домен>/apps/…`. Если нужен именно основной домен,
уточните в поддержке uCoz возможность проксирования на Node-приложение —
это зависит от тарифа.

## Откат

1. Верните прежние файлы по FTP.
2. Restart.
3. Данные восстанавливаются из копии `data/db.json` и `public/uploads`.
